# MD-04 — Deployment & Production Readiness

## Objective
Deploy the fullstack application to a free, low-friction production environment with clear, reproducible steps and zero code changes required after deployment.

## Target Platforms
- Backend: Render (Python Web Service)
- Frontend: Render (Node Web Service)
(Alternatives like Railway or Vercel should remain viable.)

## Deployment Requirements

### Backend
- Runs as a FastAPI application using Uvicorn.
- Startup is non-blocking and safe for cold starts.
- Requires environment variables:
  - TMDB_API_KEY
  - CORS_ORIGINS
- Must not rely on persistent filesystem writes for correctness.

### Frontend
- Builds successfully with `npm run build`.
- Serves production build with `npm start`.
- Requires environment variable:
  - NEXT_PUBLIC_API_URL (pointing to backend `/api` base).

## Documentation Requirements
1. A clear root README.md that includes:
   - Project overview
   - Tech stack
   - Local development instructions (backend + frontend)
   - Environment variables
2. A DEPLOY.md that includes:
   - Step-by-step deployment instructions for Render
   - Required environment variables
   - Notes on cold starts and mock-data warm-up behavior
   - Common failure modes and how to verify deployment success

## Verification Criteria
MD-04 is complete when:
- Both frontend and backend deploy successfully.
- The deployed frontend can communicate with the deployed backend.
- The game is playable in production.
- Documentation is clear enough for a new developer to deploy the app without assistance.
