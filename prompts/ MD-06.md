# MD-06 — Render Deployment Configuration (Canonical)

## Goal
Make Render deployment reproducible and “monorepo-safe” by codifying:
- required environment variables
- correct Render service settings (root dir / build / start)
- health verification steps
- optional TMDB key behavior (mock fallback)

This should eliminate “it works locally but not on Render” drift.

---

## Requirements

### 1) Add `.env.example` at repo root
Create a root `.env.example` that documents required env vars for both services:

Frontend:
- `NEXT_PUBLIC_API_URL=` (example: `https://<YOUR_BACKEND>.onrender.com/api`)

Backend:
- `CORS_ORIGINS=` (comma-separated; include your frontend Render URL and localhost)
- `TMDB_API_KEY=` (optional; if missing backend must still run using mock movies)

---

### 2) Add `render.yaml` at repo root (Infrastructure-as-Code)
Create a `render.yaml` that defines **two web services** from this repo:

#### Backend web service
- Name: `tfi-wordle-backend`
- Runtime: Python
- Root Directory: `.`
- Build Command: `pip install -r backend/requirements.txt`
- Start Command: `uvicorn backend.src.main:app --host 0.0.0.0 --port $PORT`
- Env Vars:
  - `CORS_ORIGINS` (must be set by user after frontend URL exists)
  - `TMDB_API_KEY` (optional)

#### Frontend web service
- Name: `tfi-wordle-frontend`
- Runtime: Node
- Root Directory: `frontend`
- Build Command: `npm install && npm run build`
- Start Command: `npm start`
- Env Vars:
  - `NEXT_PUBLIC_API_URL` (must be set to backend public URL + `/api`)

Notes:
- Do NOT hardcode secrets in `render.yaml`.
- Use placeholder values or omit value fields when appropriate.

---

### 3) Update `DEPLOY.md`
Ensure DEPLOY.md includes:
- A minimal “Deploy with Blueprint (render.yaml)” section
- A manual deployment section (in case user doesn’t use Blueprint)
- A checklist to set:
  - frontend `NEXT_PUBLIC_API_URL`
  - backend `CORS_ORIGINS`
  - optional backend `TMDB_API_KEY`
- A short note: “No TMDB key → mock dataset; app remains functional”

---

### 4) Verification steps (must be explicitly listed in output)
After implementation, verify:
- `render.yaml` exists and describes **two** services correctly
- `.env.example` exists and matches the app’s env usage
- `DEPLOY.md` mentions both Blueprint + Manual flows
- No new code behavior changes required beyond config/docs

---

## Acceptance Criteria
- Repo contains `render.yaml` + `.env.example` + updated `DEPLOY.md`
- Render settings are monorepo-canonical (root dirs correct)
- Deployment can proceed WITHOUT a TMDB key (mock fallback remains functional)
