# MD-06 — Canonical Render Deployment (Blueprint + Env Example)

## Goal
Make deployment to Render canonical and repeatable by adding a Render Blueprint file and a shared env example file.

## Requirements
1) Add a `render.yaml` at repo root that defines **two Render Web Services**:
   - **Backend** (Python)
   - **Frontend** (Node/Next.js)

2) Add `.env.example` at repo root documenting required env vars:
   - `NEXT_PUBLIC_API_URL`
   - `CORS_ORIGINS`
   - `TMDB_API_KEY` (optional)

3) Update `DEPLOY.md` to include a “Render Blueprint” deployment option.

4) Do NOT introduce hacks. Keep it production-canonical.

## Backend service details (Render Web Service)
- name: `tfi-wordle-backend`
- runtime: python
- rootDir: `.`
- buildCommand: `pip install -r backend/requirements.txt`
- startCommand: `uvicorn backend.src.main:app --host 0.0.0.0 --port $PORT`
- env:
  - `PYTHON_VERSION=3.9.0`
  - `CORS_ORIGINS` (required; user-supplied)
  - `TMDB_API_KEY` (optional; user-supplied)

## Frontend service details (Render Web Service)
- name: `tfi-wordle-frontend`
- runtime: node
- rootDir: `frontend`
- buildCommand: `npm install && npm run build`
- startCommand: `npm start`
- env:
  - `NEXT_PUBLIC_API_URL` (required; user-supplied) — should be backend URL ending with `/api`

## Deliverables
- `render.yaml`
- `.env.example`
- Update `DEPLOY.md` with Blueprint steps + required env var values.

## Verification
- `render.yaml` correctly points to the repo and root dirs.
- `.env.example` clearly documents values and examples.
- No application logic changes required.
- Provide a final git status check and a suggested commit message.
