# MD-02 — Backend Data Loading & Startup Stabilization

## Objective
Stabilize backend startup and data loading so the application is safe, fast, and reliable in production deployment environments (Render, Railway, etc.).

## Current Problems
1. Backend performs blocking, sequential TMDB API calls when cache is missing.
2. Backend relies on local disk writes (movies_cache.json), which:
   - May fail in ephemeral or read-only environments
   - Reset across restarts
3. Cold starts may exceed free-tier limits.
4. Core game logic may perform disk reads during requests.

## Desired End State
1. Backend startup is fast and non-blocking.
2. Movie data is loaded once per process and stored in memory.
3. No per-request disk I/O for gameplay endpoints.
4. Disk usage (if any) is optional and never required for correctness.
5. API behavior and response formats remain unchanged.
6. Concurrent requests do not trigger duplicate data fetches.

## Constraints
- No database
- No Redis or external cache
- No API contract changes
- No frontend changes required
- Use simple, deterministic, production-safe patterns

## Acceptable Implementation Patterns
- Lazy in-memory initialization
- Background-safe startup task with locking
- Singleton-style module-level cache
- Idempotent fetch logic

## Explicit Non-Goals
- Perfect real-time freshness
- Multi-instance cache coherence
- Horizontal scaling optimizations

## Completion Criteria
MD-02 is complete when:
- Backend cold start does not block on TMDB fetch
- Gameplay endpoints are fast after initialization
- Code is documented and understandable
- No new environment variables are required
