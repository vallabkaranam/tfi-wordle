# MD-13 — UX Polish & Game Presentation

## Objective
Polish the frontend UX so the Wordle-style game feels complete, clear,
and satisfying to play.

No backend changes.
No gameplay logic changes.

---

## UX Requirements

### 1) Visual Feedback (Core)
- Color-code guess results per field:
  - "correct" → green
  - "wrong" → gray/red
- Apply color consistently across the grid cells.
- Ensure colors are accessible (sufficient contrast).

---

### 2) End-of-Game Modal / Section
When game status becomes "won" or "lost":

Display a clear end-state UI that includes:
- Result message:
  - Win: “You won in X guesses 🎉”
  - Lose: “You ran out of guesses”
- Full correct answer:
  - Title
  - Hero
  - Heroine
  - Director
  - Music
  - Producer
  - Year
- Optional poster image (if available)

This section should visually stand apart from the grid.

---

### 3) Input Locking & Guidance
- Disable the search / guess input when:
  - game status != "in_progress"
- Show subtle helper text:
  - “You have X guesses remaining”
  - “Game over” when applicable

---

### 4) Guess Flow Polish
- Ensure guesses appear top → bottom in chronological order.
- Add subtle spacing or separators between rows.
- No animations required, but transitions are allowed if simple.

---

### 5) Mobile & Layout Cleanup
- Ensure grid does not overflow on small screens.
- Field labels should remain readable.
- Avoid horizontal scrolling if possible.

---

## Non-Goals (Do NOT Do)
- No backend edits
- No new game rules
- No timers
- No animations that complicate logic
- No state refactors

---

## Verification Checklist
- Colors clearly reflect correctness
- End-of-game UI appears exactly once
- Guess input locks correctly
- Game feels intuitive without instructions
- Build passes

---

## Deliverables
- Polished frontend UX
- Clean, readable components
- One commit
