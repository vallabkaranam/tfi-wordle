# MD-03 — End-to-End Fullstack Verification

## Objective
Verify that the fullstack application works correctly end-to-end using real backend data, with no functional, logical, or UX-breaking issues.

## Scope
This is a verification step. Code changes are only made if concrete issues are discovered during testing.

## Verification Areas

### Backend
1. Core API endpoints respond correctly and consistently.
2. Real TMDB-backed data is served after warm-up.
3. No crashes, blocking behavior, or inconsistent responses.

### Frontend
1. Application loads successfully and fetches backend data.
2. The game loop is playable from start to finish.
3. Guess submission, grid updates, and feedback logic work correctly.
4. Win and loss states trigger as expected.

### Integration
1. Frontend correctly consumes backend responses.
2. No CORS, network, or environment-related failures.
3. No hardcoded assumptions about data shape or size.

### UX / UI Sanity
1. Visual feedback (colors, arrows, tiles) matches game rules.
2. Inputs, buttons, and transitions are clear and intuitive.
3. No clipped icons, broken layouts, or unreadable states.

## Constraints
- Do not introduce new features.
- Do not redesign UI.
- Only fix real, concrete issues discovered during verification.

## Completion Criteria
MD-03 is complete when:
- The game is fully playable end-to-end.
- All core functionality works with real data.
- Any discovered issues are fixed and documented.
- The application is deemed READY for deployment.
