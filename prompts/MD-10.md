# MD-10 — Final Cleanup & Correctness Pass (TMDB Live Data)

## Objective
Do a final tightening pass after TMDB integration:
- remove unnecessary code/branches/files
- simplify logic
- ensure correctness and deterministic behavior
- ensure production (Render) reliably fetches live TMDB data

No new features. No gameplay changes.

---

## Scope

### 1) Simplify TMDB Auth + Config
- Canonical env var: `TMDB_READ_TOKEN`
- Keep `TMDB_API_KEY` support only if it is truly needed; otherwise remove to avoid confusion
- Update docs + `.env.example` accordingly

### 2) Simplify Fetch + Filtering
- Keep filtering minimal and correct:
  - include only released movies
  - exclude future release dates
- Avoid “fancy” heuristics
- Ensure normalization is consistent and robust (no partial fields breaking UI)

### 3) Remove Unnecessary Files/Code
- Remove unused code paths, unused helpers, unused imports
- Ensure `movies_cache.json` is either:
  - removed entirely (preferred), OR
  - clearly treated as best-effort runtime cache and excluded from git

### 4) Production Reliability
- Ensure backend fetch happens reliably on Render:
  - uses `TMDB_READ_TOKEN` when present
  - falls back gracefully when missing
- Ensure `/api/movies` reflects live TMDB data once token is set

---

## Verification
- Local: backend returns TMDB data when TMDB_READ_TOKEN is set
- Render: backend returns TMDB data when TMDB_READ_TOKEN env var is set
- Existing endpoints remain compatible:
  - GET /api/movies
  - GET /api/daily
  - POST /api/guess

---

## Deliverables
- Minimal, readable code
- Updated `.env.example` and docs
- One clean commit
